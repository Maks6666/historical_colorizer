# Image/Video colorization with PyTorch patch-GAN.

![title.png](content%20/title.png)

New approach for images colorization, which brings much better results, than simple autoencoder.
The main problem with using autoencoders in the context of image colorization is that the autoencoder perceives the entire image, 
so it colorizes it in almost the same color. To solve this problem I moved to a 
completely new approach - using a Patch Generative Adversarial Network (GAN). I also switched to using a new dataset - Places365 (https://www.kaggle.com/datasets/benjaminkz/places365), 
but I kept the idea of working with images in the LAB color space.

### GAN-concept 

![gan.png](content%20/gan.png)

Generative Adversarial Network (GAN) is based on idea of competition between two networks - generator and discriminator (or critic).
The main purpose of generator is to generate it's own data - in our case is to generate AB-channels based on L-channel and purpose of 
discriminator is to evaluate it - is it real or fake generated. So the main idea of network is to train generator to that level, when it 
will be able to generate data, which will be classified by discriminator as a real one. To train such model it needs two separate optimizers - I used Adam - 
for both networks and two separate loss functions - sometimes it's better to use BCE for discriminator and MSE + L1 for generator, but I 
used MSE for the first one too. Also, during training, it's better to make discriminator learn slower, than generator - to do this, it is 
possible to choose a lower learning rate for discriminator - for example 1e-5, when generator's could be near 1e-3. It's real common problem for GAN's,
that discriminator could overtake generator too fast. To prevent this we reduce discriminator's speed. We also could take several steps of 
generator training per one step of discriminator training - I used two generator steps per one discriminator step.
How to calculate losses of both models:

```
D_loss = ( log D(x) + log (1 - D(G(z)) ) / 2
``` 

Where:
- D - discriminator
- G - generator
- D(x) - is a probability, that real image is real
- D(G(z))  - is a probability, that fake image (generated by generator) is real
- z - data, based on which, generator generates it's prediction - could be for example L-channel of LAB image.

For real data: we want D(x) -> 1, because log(1) = 0, so penalty is minimal
For fake data: we want D(G(z)) -> 1, because log (1 - 0) = 0, so penalty is also minimal


In summary, the discriminator gains more if it outputs 1 for the real and 0 for the fake.

And this way we define a loss for generator:

```
G_loss =  - log D(G(z)) 
``` 
Here we need D(G(z)) to be closer to 1, so it's log(1) will be 0, so generator works good.

### Specificity of Patch-GAN
![patch_gan.png](content%20/patch_gan.png)

The main problem in context of image colorization is, that classical discriminators evaluate whore image and return only one number, 
which define how real image is. But Patch GAN divides an image into separate segments - patches and evaluates each of 
them separately and returns as an output a probability map, each segment of which represents it's own patch and contains 
a value, which define how realistic the patch is. This method allows the network to preprocess not the whole image per one step, but
all parts of it separately to colorize them into different colors. So it works more with local segments of image, than with whole image 
in general.

Specificity of patch GAN is hidden in it's discriminator, which main idea NOT to return just a single result of image evaluation as in usual
GAN, but to return a probability map with value of realism of each patch. It could be realised this way:

```
class DiscrConvBlock(nn.Module):
    def __init__(self, in_channels, out_channels, kernel_size, stride, padding, bnorm=False):
        super().__init__()

        self.conv = nn.Conv2d(in_channels, out_channels, kernel_size, stride, padding)

        if bnorm == True:
            self.bnorm = nn.BatchNorm2d(out_channels)
        else:
            self.bnorm = nn.Identity()

    def forward(self, x):
        return F.leaky_relu(self.bnorm(self.conv(x)), 0.2)
        
------------------------------------------------------------------------


class Discriminator(nn.Module):
    def __init__(self):
        super().__init__()

        self.net = nn.Sequential(
            DiscrConvBlock(3, 64, 4, 2, 1, False),
            DiscrConvBlock(64, 128, 4, 2, 1, True),
            DiscrConvBlock(128, 256, 4, 2, 1, True),
            DiscrConvBlock(256, 512, 4, 1, 1, True),
        )

        self.out = nn.Conv2d(512, 1, 4, 2, 1)

    def forward(self, x):
        out = self.net(x)
        return self.out(out)
``` 

But the most important part comes during models training. Here is how we train a discriminator:

```
for epoch in range(epochs):
        G.train()
        D.train()

        gen_train_loss = 0
        disc_train_loss = 0

        for l, ab in tqdm(train_dl):

            D_optimizer.zero_grad()

            l = l.to(device)
            ab = ab.to(device)

            # B, _, _, _ = l.shape

            fake_ab = G(l)
           
            fake_lab = torch.cat((l, fake_ab), dim=1)
            lab = torch.cat((l, ab), dim=1)

            D_fake = D(fake_lab)
            D_real = D(lab)

            real_labels = torch.full_like(D_real, 0.9, device=device)
            fake_labels = torch.zeros_like(D_fake, device=device)

            D_loss_real = d_loss(real_labels, D_real)
            D_loss_fake = d_loss(fake_labels, D_fake)
            D_loss = (D_loss_real + D_loss_fake) / 2


 ```

So, here, generator (G) makes a prediction based on L-channel of image and returns fake-generator AB-channels. Then, we combine it 
back into a fake LAB image and pass through discriminator to make it discriminator evaluation result = a probability map for
fake image - D_fake and passing real LAB image through discriminator, we receive a probability map for real image. Then we create a
labels matrices fulled with zeros - fake_labels for fake probability map and fulled with values close to 1 - 0.9 - real_labels - for 
real probability map. Then we calculate losses with MSE between real_labels and D_real and between fake_labels and D_fake to define 
how correct discriminator prediction was. And then, according to formula of D_loss, we calculate total discriminator loss as D_loss.

And this way we handle a generator:

```
for _ in range(g_step):
    G_optimizer.zero_grad()

    fake_ab = G(l)
                
    fake_lab = torch.cat((l, fake_ab), dim=1)
    G_adv_loss = g_loss(D(fake_lab), real_labels)
    G_l1_loss = F.l1_loss(fake_ab, ab)
 
    G_loss = G_adv_loss + G_l1_loss * lamda_l1

```

Here we calculate MSE between probability map, which discriminator returns after handing fake generated image and real labels to 
make discriminator 'believe' that fake generation is real. We also calculate L1 loss between fake and real AB channels. Important:
here, we pas through discriminator whole LAB-image to receive it's probability map.

It is also important to mention, that in case of GAN, usage of such metrics as SSIM or PSNR is almost senseless and it is always
better to evaluate quality of generated data visually, which is realised in my train() function is "gan_training.ipynb" file.

### Architecture 
![generator.png](content%20/generator.png)

As a main idea for generator architecture, I used pretty same approach, as in autoencoder version of colorization project - it 
is a custom U-net based autoencoder network with skip connections and squeeze-excitation blocks for better detail memorizing.
It accepts a L-channel image and returns AB-channels, but with custom method "predict" it will return RGB-image. Total weight
of model is 90 mb. For more details see a previous version README or gan_training.ipynb file. 
Code of discriminator is available in same file as well or in this README
above. The idea here is, that to make generator more advanced and to reduce parameters of discriminator to prevent it's prevail. 

![discriminator.png](content%20/discriminator.png)

Total weight of discriminator is smaller, which allows to prevent discriminator prevail over generator during training process.
